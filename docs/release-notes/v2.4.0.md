# Plöttr v2.4.0 "Log Book" — release notes

Volcano reads tables the way labs actually export them. A p-value column that is already
−log₁₀-transformed is recognised and plotted correctly, and a column holding your own
significance calls colours the points and draws the boundary those calls imply. Points can also
be drawn as open circles, and every tool accepts files up to 4 MB. Statistical results for
existing files are unchanged.

## ✨ Added

### Volcano: p-value columns that are already log-transformed

Volcano used to assume the p column held raw p-values and took −log₁₀ of it again. A
−log₁₀(padj) value such as 5.2 then read as "p = 5.2": every gene was classed as not significant
and the points sat at or below zero, with no warning.

- **"Values are: p | −log₁₀ p | log₁₀ p"** on the Configure step, under the p column.
- **Set automatically** whenever a p column is picked. Mostly negative values read as log₁₀ p
  (sign kept), any value above 1 as −log₁₀ p (no p-value can exceed 1), and values between 0 and
  1 in a column whose name mentions "log" as −log₁₀ p. A note under the switch says which rule
  applied; the user can override it.
- **Exact at the extremes.** For log-scale input the column's own value is the y position, so a
  −log₁₀ p of 350 is drawn at 350 even though 10⁻³⁵⁰ is too small for a double and becomes 0.
  Those genes are not reported as "p = 0, clamped".
- **Everything follows:** the p cutoff, the up / down / ns classes and the top-hit labels use p
  converted back from the column; the CSV writes the file's own −log₁₀ values; the R script
  carries them and derives `pvalue <- 10^(-nlog10p)`.
- **Column names** like `-log10(padj)` or `mlog10_pval` are now auto-picked as the p column (a
  plain `padj` still wins when both exist), and a log-named column keeps its own name as the
  y-axis title.

A column of −log₁₀ values that all fall between 0 and 1, with no "log" in its name, cannot be
told apart from plain p-values and stays "p" unless the user switches it.

### Volcano: the boundary implied by your own significance calls

Many pipelines export a column of their own calls (`significant` = yes / no, + / −, + / empty).
Volcano can now use it instead of the p and log₂FC cutoffs.

- **An optional "Significance call" column** on the Configure step. It is picked automatically
  when a column is named like `significant`, `sig`, `is_significant` or `DE` and every value
  reads as a call: yes / no, + / −, + / empty, true / false, 1 / 0, significant / ns. Values that
  do not read as a call count as not significant, and Configure lists them.
- **The calls colour the points**: significant genes are up or down by the sign of log₂FC. The
  Thresholds tile and the summary strip say the cutoffs do not apply.
- **The boundary.** The straight cutoff lines give way to the curve y = c / |log₂FC| that
  separates the calls. With each gene's score s = |log₂FC| × −log₁₀ p, lo is the largest score
  among non-significant genes and hi the smallest among significant ones. If lo < hi, the curve
  is drawn at c = (lo + hi) / 2 as a dashed line, with a shaded band from lo to hi showing how
  tightly the calls pin it down. It is labelled "boundary implied by the significance calls",
  never as an FDR threshold, in a legend strip below the x-axis title.
- **Symmetric by default.** Calls are usually made the same way on both sides (two-sided tests,
  one |log₂FC| threshold), so both sides are fitted together on |log₂FC| and the one curve is
  mirrored; a sparse side borrows its constraint from the other. The shared band is the overlap
  of the two sides' own bands, so it separates each side's calls as well as a per-side curve
  would. Only when no symmetric curve fits (the calls look asymmetric) is each side fitted on its
  own, and only the sides that fit are drawn.
- **Only where the data support it.** A fit needs at least 3 significant and 3 non-significant
  calls, and is drawn only over the |log₂FC| range of the genes it was fitted on. When nothing
  fits, nothing is drawn and the Thresholds tile says whether there were too few calls or the
  calls overlap ("calls not separable by a single curve").
- **Exports:** the CSV classes follow the calls; the R script carries a `significant` vector,
  classifies from it, and draws the same band and dashed curve per side with `geom_ribbon` /
  `geom_line`, noting which fit applied and why any side was left out.

Calls made with straight cutoffs (for example padj < 0.05 together with |log₂FC| > 1) form a
rectangle rather than a curve, so on such files a single curve usually cannot separate them and
the tile says so.

### Volcano: filled or open points

A **Points: Filled | Open** choice in the Style tab draws the points as solid discs or as open
circles in the same colours. It works with or without colour / size mapping (mapping still sets
each outline's colour and radius, Point alpha its opacity), and the size legend's sample circles
follow. It carries into SVG and PNG exports, including the large-dataset path that redraws the
canvas as vector circles, and into the R script (`shape = 1`). Clicking a hollow centre still
labels the point. Saved settings without the option start on Filled.

## 🔧 Changed

### Files up to 4 MB

Every upload and paste box now accepts files up to 4 MB (was 2 MB) and warns above 2 MB (was
1 MB). A sweep at 2 / 4 / 6 / 8 MB of synthetic data through every plot tool measured, at 4 MB,
load times of about 2.5 s or less for realistic file shapes (Scatter, drawing one SVG element
per point, was the first to struggle beyond that). The limit is one pair of constants,
`FILE_LIMIT_BYTES` / `FILE_WARN_BYTES` in `_shell/FileDropZone.tsx`, and the "max" hints and
too-large messages in both languages say 4 MB.

### A bare `+` or `-` is not flagged as formula injection

The formula-injection check flagged every cell starting with `=`, `+`, `-` or `@`, so a +/−
significance column lit up the warning banner on hundreds of cells. A cell that is exactly `+`
or `-` is stored as text by every spreadsheet (nothing follows the sign to evaluate) and is no
longer flagged or escaped. Anything longer (`+A1`, `-cmd|…`, `++`) is still flagged and
neutralised on export.
