# Plöttr v1.10.0 "Vanishing Point" — release notes

An Aequorin release: a new calibration method for labs that report relative
rundown rather than absolute [Ca²⁺], plus two display fixes so its
near-zero values don't get crushed to an uninformative "0" on the chart.

## ✨ Added

### L/Lmax (fractional rate) calibration for the Aequorin tool

A fourth calibration option alongside Allen & Blinks (1978), the Hill
equilibrium, and the generalised Allen & Blinks form:

```
k(t) = L(t) / Σₜᵉⁿᵈ L
```

The classical fractional luminescence rate — instantaneous luminescence over
the light still to be emitted from t to the end of the recording (the
"remaining pool"). Unlike the other three formulas, the denominator here is
time-varying rather than a fixed whole-trace total, and the result is a
dimensionless ratio in `[0,1]`, not a calcium concentration — so it needs no
Kr/Ktr/Kd/n parameters at all.

Implementation: `calibrateFractionalRate` (`tools/aequorin/helpers.ts`)
computes the remaining-integral denominator with one backward pass per
column (an O(n) running suffix sum), rather than an O(n²) nested sum. A
`null` input stays `null`; a zero remaining-sum denominator (an all-null
tail, or the very last non-null row) also yields `null` to avoid dividing by
zero. It deliberately diverges from the other three formulas on one point: a
zero luminescence _value_ is not itself nulled out, since `k(t) = 0` is a
meaningful "no rate yet" reading here rather than the non-physical artifact
it would be for a Ca²⁺ conversion.

The formula picker, the live substituted-equation preview, the Y-axis label,
and both English and French copy were all extended to cover the new option.

## 🐛 Fixed

### Auto Y-axis range and tick labels collapsed to zero for small-magnitude data

Two related bugs surfaced immediately once real L/Lmax data (values
clustering well under 0.1) hit the existing Y-axis machinery, both rooted in
the same assumption: that axis numbers are always ≥ 1.

- **Auto-range padding** (`computeAutoYRange`) rounded both padded bounds to
  a fixed 2 decimal places. For a dataset ranging over, say, 0.003–0.05, that
  rounds `yMin` and `yMax` to the same `0.00`/`0.05`-ish pair or worse,
  collapsing the axis and forcing the user into manual Y-min/Y-max entry.
  Rounding precision (`autoYDecimals`) now scales with the data's own
  magnitude — values ≥ 1 keep the original 2 decimals unchanged (raw RLU,
  [Ca²⁺] in µM), smaller magnitudes get proportionally more decimal places.
- **Tick-label formatting** used a plain `t.toFixed(1)`, which renders
  anything under 0.05 as `"0.0"` — indistinguishable from an actual zero on
  the chart. The new `fmtYTick` (`tools/aequorin/helpers.ts`) switches to
  exponential notation (e.g. `1.5e-2`) below 0.01 and above 10000, matching
  the convention already used by the scatter tool's axis ticks. Wired into
  both the main time-course chart and the inset Σ barplot.
